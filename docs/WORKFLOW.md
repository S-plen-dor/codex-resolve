# 自然语言剪辑工作流

## 用户对话

用户指定素材和意图后，Codex 检查现有分析与当前工程，自主完成常规创作决定。影响结果的缺失信息才询问；用户授权制作后不逐镜头征求许可。用户明确要求先讨论时保持只读。

先构建可观看初稿，再按“太碎、放大一点、保留完整动作”等反馈修订。模糊指代先结合当前预览和上下文定位；无法唯一定位且会改错时再询问。

## 项目记录

- project.json：素材、目标输出、主音源、输入色彩与目标工程。
- state.json：阶段、当前计划与预览、已认可决定、未决问题和下一步。
- plans/：版本化剪辑计划，稳定镜头 id；修改前保留旧计划。
- HANDOFF.md：简短交接，新聊天先读它和两份 JSON，再按需读取分析。
- versions/：记录检查点；Resolve 工程备份另外导出，不能假定这里已经备份工程。

路径属于用户本机项目，不能上传到开源仓库。首次生成的输出规格为空，Codex 从当前任务与实际素材补全，不继承固定 4K、竖屏或 59.94。

## 执行前后

明确目标工程和工作时间线，检查未保存状态与渲染状态。保留可恢复版本，不在正式交付时间线上试验未知操作。素材分析与计划修改可自主完成；当前未实现的执行器能力需要可用官方 API 或已连接工具支持，不能假装调用了不存在的命令。

使用有理帧率和明确帧边界，核对实际插入时长、源绑定、关键帧与声道。输出渲染后按本次用户约定检查；若要求跳过检查，明确记录 skipped，不宣称通过。

## 迭代与交付

“恢复上一版”先定位具体版本与工程备份，项目记录检查点本身不能还原 Resolve。“保留其他部分”需要比较新旧计划，保持无关镜头的决定与参数。当前通过全量构建新的工作时间线迭代，不声称原地增量修改。

交付说明成片位置、可编辑工程、修改内容、验证范围及未解决问题，更新交接记录。发布、上传、删除或替换用户文件遵循当前授权范围。
