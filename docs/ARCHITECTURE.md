# 架构

## 产品入口

Codex 对话是入口。工作流服务已安装 Codex 与 Resolve 的用户，不要求用户手写 JSON。计划和状态由 Codex 维护，用户可用自然语言要求查看、修改或恢复。

## 模块与协议

1. 创作决策：需求 → 素材事件候选 → 乐句/动作理解 → 剪辑计划。分析结果保留证据和置信度，不将频谱瞬态称为确认强拍。
2. 可选视觉：接收真实素材与创作意图，输出可编辑设计、遮罩或透明视频；交接包含尺寸、帧率、时长、入点、Alpha、色彩约定与源文件。
3. 执行：通过 Resolve/Fusion 实现可编辑工程；FFmpeg 负责媒体辅助处理。官方 API 不能完成的步骤记录原因，优先经过验证的替代路径。
4. 验证：技术解码、音频/画面对照、代表段观看及创作评价分开报告，发现问题返回计划修订。
5. 共享状态：project.json、state.json、版本化 plans 与 HANDOFF.md。每次副作用记录目标、输入、结果和恢复位置。

## 计划约定（草案）

examples/edit-plan.example.json 是需替换真实素材的协议示例，已有同帧率多轨与组合效果执行器。每个镜头有稳定 id、素材 id、源区间、时间线区间、剪辑理由及效果参数。project_root 相对计划文件目录解析，素材路径相对项目根目录。资产 id 不随重命名自动改变。当前结构检查支持区间、同轨重叠、路径和可选内容哈希；执行前另检查实际时基与规则时间戳。

帧索引零起点、区间 [start,end)，帧率用 numerator/denominator 字符串。必须区分素材、输出时间线、镜头局部及 Fusion 时间。变速保存显式源映射，主音轨策略按项目确定。同步多机位共用同步轴；不同演出场次需分段匹配，不能套全片偏移。

## 创作自由与可靠执行

Codex 自主选镜、设计节奏并根据反馈修订。稳定重复操作进入工具库；一次性效果先作为项目专用实现，明确状态后再提升为公共能力。不要将个人偏好、固定慢放值、歌曲参数写入通用规则。

规则分三类：

- 执行约定：时间基、接口前置条件、目标工程确认、恢复记录与真实结果报告，保障操作正确。
- 项目创作决定：画幅、节奏、卡点、构图、动作完整性、变速、声音、色彩与人物表现，由当前用户和素材决定，可通过对话随时调整。
- 可选参考：案例、配方、风格预设与外部 Skills，按需采用，不默认启用，也不作为创作白名单。

自主创作时 Codex 应根据当前素材提出判断，不预设统一审美。用户的明确指示优先于默认建议；将推断记录为项目决定而非永久规则。用户主动启用的个人偏好应与公共规则分开保存，不向其他用户或无关项目传播。

能力扩展以参数化基础操作和可组合效果为主，避免把单一风格写死成唯一工作路径。某个慢放 helper 只支持特定速度，意味着需要其他实现才能超出范围，不能推导为用户不应选择该速度。QC 区分意图内效果与意外缺陷；“黑帧候选”“不同步”等检测结果应结合计划解释，创作质量不由统一分数决定。

未来执行器必须以唯一操作 id 和工程状态核对避免重复插入。失败后在已记录步骤恢复，而非盲目重跑。当前 checkpoint 保存项目事实、状态、人工/自动交接和创作意图，不备份计划目录、媒体、Fusion 或 Resolve 数据库；这些需要单独版本化与导出。

## 接入顺序

Python CLI 与官方脚本桥优先；MCP 是可选适配器，不作为首版运行前提。不重新实现 NLE、光流引擎或视觉 Skill。

## 当前闭环实现（未运行验证）

observe 组织视觉证据；plan-validate / plan-diff 支持计划与版本比较；plan-apply在显式目标工程中保存与备份后创建新时间线，接入有限camera/opacity/慢放与独立音频；render-submit / render-status 提供预览任务交接。Codex 自身负责观察、创作与反馈定位，命令不自动产生审美判断。命令、范围和副作用见 [CREATIVE_LOOP.md](CREATIVE_LOOP.md)。

可选 --workspace 将 CLI 结果与项目关联，合作式锁防止同时推进；事件含 state_after，state.json 原子替换，HANDOFF.auto.md 自动生成。plan-register 选择当前计划，resume 只读续接并检测缺失文件/计划外部改动。plan-locate 辅助时间区间定位，plan-revise 依据基础哈希和可选镜头保护生成新计划。自然语言解释仍属于 Codex，当前没有自动事件重放或原地增量修改。
